# 用 Python 从零实现 Coding Agent SDK

给一个程序一句“修复这个测试失败”，它如何找到代码、修改文件、运行测试，并在失败后继续尝试？本教程从这个问题出发，逐步构建一个可嵌入其他应用的 Coding Agent SDK。

目标是理解并实现 OpenHands 式软件 Agent 的主要边界：Agent 负责决策，工具负责描述操作，执行环境负责操作落地，Conversation 负责状态与生命周期。最后让终端程序和远程服务都使用同一个 SDK。

## 阅读前需要知道

需要了解 Python 函数、类、类型标注、异常和基本命令行操作。异步部分会解释 `async`、`await`、任务取消的用途。建议使用 Python 3.11 或更高版本；本地命令与容器章节以 Linux 为验收环境，macOS 和 Windows 的进程控制另行适配。

前半程使用脚本化模型，不需要 API Key。脚本化模型用于确定性地检查框架行为，接入真实模型后再观察实际编码效果。两者的验收要分开：一次模型恰好修好了 bug，不能证明框架能正确处理取消、崩溃和恢复。

本版是**实现前的教程初稿**。第一章提供完整的独立小例子；后续章节提供关键实现片段、接口契约、组装步骤与验收案例。标为“核心片段”的代码需要放入指定模块并补齐文中说明的外围逻辑，不应把零散片段直接拼成生产程序。章节代码落地后，再补上实际提交或 tag 链接，并逐项记录验证结果。

## 每章的开发顺序

1. 阅读问题和数据流，理解本章为什么增加这个抽象。
2. 在 `examples/` 中写出最小调用方式，再实现它所需要的 SDK 行为。
3. 用脚本化模型与临时目录验证确定性行为。
4. 完成本章异常场景，不只运行成功路径。
5. 更新章节示例与实际 API，记录本章实现状态。

代码逐章累积，保留每章示例，而不是维护七份彼此分叉的完整框架。未来可用 `chapter-01` 等 Git tag 固定章节版本；这些 tag 目前尚未创建。

## 贯穿全书的练习

练习仓库包含一个有错误的 `add(a, b)` 与对应测试。先让 Agent 发现失败，读取函数，把 `a - b` 改为 `a + b`，再运行测试，最后报告具体变更与结果。先用脚本模型固定操作序列，再用真实模型自主选择操作。

后半程在同一练习上增加三个问题：执行中取消怎么办？工具已执行但进程崩溃怎么办？浏览器断开以后如何查看任务结果？这样每个新机制都有明确用途。
