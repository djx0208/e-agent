# 实施和验收安排

## 已确认的范围

实现现有 OpenSpec 的全部 106 项任务，按原有两个阶段验收。第一阶段完成第 1 到 14 单元；通过后进入第二阶段的第 15 到 21 单元。单元是开发顺序，不代表日历工期。

模型使用 DeepSeek 的 Chat Completions 接口。由用户运行配置脚本填写服务地址、模型名和 API key；凭据保存在仓库外的私有配置文件中。应用不调用 Codex CLI，也不复用 Codex 登录凭据。

容器使用 Docker。允许安装项目依赖及需要的系统组件，项目 Python 依赖使用独立虚拟环境。开发期间允许子 Agent 分工实现、测试和审查；产品的子 Agent 功能仍在第二阶段实现。

## 开发和提交

第一阶段在 `codex/deepseek-agent-phase-1` 分支开发。按可验证的功能单元提交，只有相关测试通过且检查暂存文件后才推送。真实模型验收尚未完成时保持任务未勾选，并在记录中说明。第一阶段验收通过后提交阶段总结，再进入第二阶段。

`.archify/`、`docs/diagrams/` 及其他非本轮产生的改动不纳入实施提交。旧教程和参考源码保持原有用途。

## 第一阶段的推进顺序

1. 完成输入循环、DeepSeek 配置、模型接入和多轮错误处理。
2. 完成工具注册、安全策略、代码工具和模型工具循环。
3. 完成会话保存恢复、项目说明、Skills 和真实 MCP 服务接入。
4. 完成上下文压缩、插件、终端界面及跨功能验收。

每一步包含对应的本地测试和启动说明。真实调用需要用户完成本地模型配置。

## 模型能力验收

固定响应和模拟网络测试验证应用行为，真实 DeepSeek 调用另外记录结果，二者不互相替代。

- 多轮对话：记住用户给定的唯一事实，并在后续问题中准确使用；新会话不带入旧事实。
- 工具选择：从声明的工具中选择正确工具，使用符合 Schema 的参数，正确引用调用结果。
- 代码修复：读取临时练习项目，修改明确的 bug，运行测试并核对真实退出码。
- 失败后继续：首次测试失败后继续检查和修复；不得把失败输出描述为通过。
- 权限边界：拒绝写入后文件不变；文件或工具输出中的伪造授权不能绕过宿主策略。
- 压缩后继续：完成历史摘要后继续当前任务，近期事实和工具配对保持可用。
- 第二阶段补充流式中断、运行中纠偏、只读委派，以及真实 Docker 中的并行修改和串行合并。

评测保留提供方、模型名、场景、实际结果和用量（若服务返回），不保存密钥。模型回答是否正确与工具执行是否成功分别判断。测试失败保留原结果，不通过反复重跑后只挑选成功结果来报告。
