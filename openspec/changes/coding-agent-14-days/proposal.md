# Proposal

## Why

目前项目只有教程草稿和参考源码，尚未实现 Agent。原方案同时引入 SDK、执行服务和管理平台，学习步骤过大；先用 14 个逐步累积的目标完成一个本地 Python Coding Agent，再用第二阶段补齐交互与多 Agent 协作。

## What Changes

- 按 REPL、模型、代码工具与循环、Session、Skills、MCP、上下文压缩、插件和 CLI 界面的顺序开发，每天有可演示结果和验收条件。
- 先做终端输入与退出，再接真实模型；第一天无需模型密钥。
- 在 14 天内支持读取文件、精确修改文件、运行命令，并根据结果继续执行。
- Session 保存一段对话及工具记录，支持新建、列出、切换与恢复。
- 使用项目根目录的 `AGENTS.md` 保存固定说明，不做独立记忆库或 `/memory` 命令。
- 支持 Skills 发现与按需加载，通过 MCP stdio 服务接入外部工具。
- 支持手动和自动上下文压缩，保留原始 Session 历史，压缩后继续任务。
- 支持本地插件注册工具、命令和执行前后回调，不做插件市场和热更新。
- 第一阶段最后改善终端输出、工具进度和输入体验，并完成修复 bug 的验收。
- 第一阶段将统一权限判断、敏感信息保护、不可信内容处理和执行前复查加入原有 14 天验收。
- 第二阶段按第 15 到 21 个开发单元推进事件与流式输出、运行中输入、无界面运行接口、只读子 Agent、隔离写入与协作验收。
- 子 Agent 使用独立上下文，权限不超过父任务，统一管理预算、取消、记录和恢复；并行写入采用独立 worktree 和受限执行环境。
- 按用户确认开始实现全部任务，使用 DeepSeek 接口和 Docker，分阶段完成本地与真实模型验收。教程暂不改写。

## Capabilities

### New Capabilities

- `terminal-repl`：终端输入循环、内置命令、退出与中断。
- `model-chat`：可配置模型调用、多轮消息、错误处理。
- `coding-tools`：统一工具注册、参数校验、项目内文件与搜索工具、命令执行和模型工具循环。
- `local-sessions`：本地会话记录、新建切换、保存与恢复。
- `project-memory`：从项目说明文件加载固定约定，保留原能力路径但不建立独立记忆系统。
- `agent-skills`：发现、列出并按需加载 `SKILL.md`。
- `mcp-tools`：连接显式配置的本地 MCP 服务，发现与调用工具。
- `context-compaction`：手动及自动摘要、完整工具组保留、失败回退与恢复。
- `local-plugins`：显式加载本地插件，注册工具、命令和受限生命周期回调。
- `cli-presentation`：清晰的回复、工具状态、会话信息与普通文本输出。
- `execution-safety`：统一权限策略、敏感信息保护、不可信输入及执行前复查，第一阶段完成。
- `agent-runtime-events`：第二阶段的运行事件、流式回复、工具进度和生命周期通知。
- `headless-execution`：第二阶段的无界面单次运行、结构化输出和可调用接口。
- `agent-delegation`：第二阶段的子 Agent 委派、并发、预算、取消及恢复。
- `isolated-workspaces`：第二阶段的命令隔离、独立工作副本、变更审查及合并。

### Modified Capabilities

无。当前没有已有能力规格。

## Impact

后续实现新增单个 Python 应用及测试，暂不拆多个发行包。初步采用 HTTPX 请求模型，界面阶段再引入 Rich 和 prompt_toolkit；MCP 使用官方 Python SDK，工具参数使用 JSON Schema 校验。

现有 `docs/tutorial/` 是旧的 SDK 方案，不作为本轮实现范围；发生冲突时以本变更为准。第二阶段提供应用内运行接口及本地容器隔离，但暂不发布独立 SDK。Web 管理平台、远程执行服务、远程 MCP 与 OAuth、插件市场、向量检索仍留到后续。OpenHands 保留为代码阅读参考，不作为运行依赖。

名称中的 14 天保留为第一阶段标识；第 15 到 21 单元属于第二阶段，均不绑定日历工期。第一阶段验收通过后才开始第二阶段，全部任务完成后才考虑独立 SDK 发布。
