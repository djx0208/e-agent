# Spec Delta

## Purpose

在第二阶段为并行修改提供独立工作副本，并限制命令对宿主文件、凭据和网络的访问。子任务结果先供审查再串行合并，避免并行覆盖用户改动，并保留失败后的可检查状态。

## ADDED Requirements

### Requirement: 受限执行不可降级

受限命令 SHALL 在经过预检的本地容器中执行，默认断网、非特权、资源有界，仅当前副本可写。宿主凭据、主项目 Git 元数据、其他副本和容器管理接口 SHALL 不可访问；隔离不可用时拒绝，不回退宿主执行。

#### Scenario: 缺少容器环境
- **WHEN** 用户请求运行隔离 worker 但预检失败
- **THEN** 任务不启动宿主命令，显示缺少的条件

#### Scenario: 读取宿主资源
- **WHEN** 容器命令尝试读取宿主凭据或访问网络
- **THEN** 访问被隔离边界阻止，失败作为真实结果返回

### Requirement: 独立副本和用户修改保护

并行 worker SHALL 使用独立 Git 工作副本和记录的基线。非 Git 或主工作区不干净时 SHALL 拒绝创建，不能自动暂存、重置或丢弃用户改动。

#### Scenario: 项目有未提交修改
- **WHEN** 用户申请启动可写 worker
- **THEN** 启动被拒绝，用户文件、暂存区及未跟踪文件保持原状

### Requirement: worker 操作仍需批准

worker 写入和命令 SHALL 通过父协调者逐次审批，显示子任务身份及实际操作；无审批通道默认拒绝。worker SHALL 不使用宿主插件或 MCP 绕过隔离。

#### Scenario: 批准委派后请求执行命令
- **WHEN** 父用户批准创建 worker，worker 随后申请命令
- **THEN** 程序为具体命令重新请求批准，不复用委派授权

### Requirement: 审查后串行合并

子任务完成 SHALL 仅产生差异和结果，合并 SHALL 由父协调者串行执行并重新确认基线、主目录状态、路径策略和批准。冲突或状态变化 SHALL 停止合并，不覆盖主目录。

#### Scenario: 主项目在审查期间变化
- **WHEN** 用户审查差异时主目录出现新改动
- **THEN** 原批准失效，合并停止并保留副本

#### Scenario: 合并后验证失败
- **WHEN** 已批准合并完成但测试失败
- **THEN** 显示失败并保留差异和退出码，不报告修复成功或自动回滚用户改动

### Requirement: 清理与失败保留

取消 SHALL 停止受管理容器；结果未知或失败副本 SHALL 默认保留。仅已明确接收或丢弃的副本可清理，不因父任务退出而删除未处理结果。

#### Scenario: worker 取消后结果未知
- **WHEN** 容器停止状态无法确认
- **THEN** 记录未知、停止后续操作并保留副本供核查
