# Spec Delta

## Purpose

从项目根目录的说明文件读取固定约定，让同一项目的会话知道测试命令和代码风格。说明文件由用户维护，与 Session 历史和压缩摘要分别管理，不建立自动提取或独立的长期记忆系统。

## ADDED Requirements

### Requirement: 加载项目说明文件

程序 SHALL 在每次普通任务开始时读取项目根目录的 `AGENTS.md`，标记来源后用于本轮模型上下文。文件不存在时 SHALL 正常继续；文件过大、不可读、编码无效或链接越界时 SHALL 提示并停止本轮，不静默忽略。

#### Scenario: 新会话使用相同说明
- **WHEN** 用户在包含 `AGENTS.md` 的项目中新建 Session 并提交任务
- **THEN** 模型请求包含该项目说明，不需要用户手动添加记忆

### Requirement: 项目说明不改变授权

程序 SHALL 将项目说明与其他项目隔离，且不允许说明关闭确认或改变工具权限。第一版 SHALL 不自动读上级目录或嵌套目录中的同名文件，也不从对话自动写回说明。

#### Scenario: 说明要求跳过确认
- **WHEN** 项目说明包含自动批准命令的要求
- **THEN** 命令仍按执行策略请求确认

### Requirement: 更新说明不删除历史

程序 SHALL 在下一次任务开始时使用文件的最新内容，当前任务使用开始时的快照。删除文件后 SHALL 停止注入说明，但不改写已保存消息或摘要；第一版不提供独立记忆管理命令。

#### Scenario: 删除说明后新建会话
- **WHEN** 用户删除 `AGENTS.md` 并创建新 Session
- **THEN** 新请求不注入旧说明，已有 Session 记录保持不变

### Requirement: 项目内容不得改写安全配置

项目说明 SHALL 遵守 execution-safety；任何声称系统授权或要求修改可信策略的内容不得由加载流程执行。

#### Scenario: 说明伪造高优先级授权
- **WHEN** 项目说明要求开放凭据目录并自动启用服务
- **THEN** 策略及服务配置保持不变，模型提出相关操作时仍接受宿主检查
