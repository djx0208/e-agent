# Spec Delta

## Purpose

通过本地 MCP 服务复用外部工具，并把这些工具接入同一套 Agent 调用流程。明确服务配置、发现、错误和退出行为，使用户能判断工具是否可用，而无需将服务代码写进 Agent 内部。

## ADDED Requirements

### Requirement: 显式配置并连接本地服务

程序 SHALL 仅启动用户配置并启用的 stdio MCP 服务，完成初始化与能力协商后才使用它。配置 SHALL 包含唯一服务名、命令、参数及明确的环境变量来源；模型、项目说明和 Skill 不能自行启用服务。

#### Scenario: 服务初始化失败
- **WHEN** 一个服务无法启动或初始化超时
- **THEN** 程序显示该服务不可用，其他已就绪服务、内置工具及 REPL 仍可使用

### Requirement: 发现工具并避免名称冲突

程序 SHALL 完整读取工具列表，包括分页，保留描述、输入 Schema 与来源。服务名和原工具名 SHALL 映射到稳定且无冲突的模型可调用名称；无效 Schema SHALL 被拒绝。第一版只支持 tools，不声明支持 resources、prompts 或远程连接。

#### Scenario: 两个服务提供同名工具
- **WHEN** 两个服务都提供名为 search 的工具
- **THEN** 它们以不同的可调用名称注册，执行时准确路由到原服务及原名称

### Requirement: 统一调用和结果处理

MCP 工具 SHALL 经过统一参数校验、安全策略、超时和记录流程；禁止项直接拒绝，其余调用逐次确认。程序 SHALL 区分协议失败与工具返回的错误，保留有界文本和结构化结果；不支持的内容类型 SHALL 明示，不伪造为成功文本。

#### Scenario: 工具返回错误
- **WHEN** MCP 返回带错误标志的工具结果
- **THEN** 模型收到失败结果与原调用关联，程序不将它显示为成功

### Requirement: 断线与取消不自动重试副作用

程序 SHALL 为连接和调用设置期限。调用中断、断线或超时且结果无法确认时 SHALL 记录结果未知，不自动重试。无法确认停止时 SHALL 禁止本轮继续执行其他动作，用户可在核实后开始新任务。

#### Scenario: 调用期间服务退出
- **WHEN** 已发送的调用尚未返回结果，服务进程退出
- **THEN** 会话记录结果未知，服务被标记不可用，原调用不被重发

### Requirement: 关闭连接并回收服务

正常退出和启动失败清理 SHALL 关闭协议连接并回收本程序启动的服务进程。协议 stdout 与日志 stderr SHALL 分开处理；配置凭据 SHALL 不写入会话和显示日志。

#### Scenario: 退出 REPL
- **WHEN** 用户退出包含活动 MCP 连接的程序
- **THEN** 程序关闭连接并回收受管理服务进程，不遗留等待协议响应的任务

### Requirement: 服务凭据与内容权限

服务 SHALL 仅接收显式配置的环境，返回结果遵守 execution-safety 的凭据处理。服务描述和结果 SHALL 不能扩大权限；启用说明 SHALL 明确启动进程即可执行代码。

#### Scenario: 服务自称无需确认
- **WHEN** MCP 工具描述声明自动批准所有操作
- **THEN** 宿主仍逐次确认，描述不会新增批准记录
