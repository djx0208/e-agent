# Design

## Context

项目尚无 Agent 实现，现有教程是旧的 SDK 草案。范围以 [proposal.md](proposal.md) 和本变更的能力规格为准。用户已确认按阶段实现全部任务，模型使用 DeepSeek 接口，容器使用 Docker；暂不改写旧教程或参考源码。

## Goals / Non-Goals

**Goals:**

- 用 Python 3.11+ 在 Linux 单用户本地环境完成一个小型 Coding Agent。
- 先完成 REPL、模型和工具，再加入 Session、Skills、MCP、压缩及本地插件。
- 内置工具、MCP 工具和插件工具使用相同注册与执行流程。
- Session 保留完整记录，发给模型的上下文允许压缩。

**Non-Goals:**

- 不做独立记忆库、自动长期记忆、向量检索或 `/memory` 命令。
- 不做插件市场、热更新、远程 MCP、OAuth、MCP resources/prompts。第一阶段不做多 Agent 或命令隔离；第二阶段仅支持本地父子任务及容器执行，不承诺隔离恶意宿主插件。
- 不在本轮提取发布 SDK 或建立管理平台。模型流式显示及应用内运行接口安排在第二阶段。

## Decisions

### 按需要增加模块

第一天只增加 `main.py` 及测试，使用标准输入输出。模型、工具、Session、上下文和扩展模块在对应阶段才加入，最终仍是一个应用，不拆多个发行包。

REPL 负责输入和命令分发；模型模块负责协议转换；Agent 循环负责请求模型和执行工具；Session 负责原始记录。Skill 与项目说明是输入材料，MCP 和插件是扩展来源，均不另建 Agent 循环。

### 模型与执行方式

第二天用 HTTPX 的异步客户端连接 Chat Completions 兼容服务，由应用持有一个 asyncio 事件循环，后续复用给 MCP。基础 CLI 仅在没有运行任务时读取同步输入，运行中通过取消当前任务响应 Ctrl+C。不建立额外线程中的常驻 MCP 连接，避免跨事件循环使用客户端。第二阶段再让输入与运行并发，二者仍使用同一应用事件循环。

配置来自用户运行脚本写入的仓库外私有模型配置，支持 `E_AGENT_BASE_URL`、`E_AGENT_MODEL`、`E_AGENT_API_KEY` 环境变量覆盖；基础地址不包含 `/chat/completions`。缺少配置不影响帮助或退出。验证结束原因、工具参数、调用 ID；鉴权、限流、网络及格式错误明确展示。普通请求不自动重试；第十二天仅为确认的上下文超限增加一次压缩恢复。

测试用固定回复或模拟 HTTP 响应，真实模型验收单独记录。内部消息先用简单数据结构，无需引入大型 Agent 框架。

### 统一工具注册与执行

第四天定义工具的唯一名称、描述、JSON Schema、来源和执行入口。使用 JSON Schema 验证器检查参数；无效或不支持的定义拒绝注册。主循环只面向注册表，不判断工具来自内置模块、MCP 还是插件。

第五天实现 `read_file`、`write_file`、`edit_file`、`find_files`、`search_text`、`run_command`。文件路径以 `--project` 或启动目录为根，拒绝越界和外链；搜索返回相对路径与行号，按行读取保留版本标识。新建拒绝覆盖；编辑核对内容哈希并要求原文恰好匹配一次。读入字节计算哈希，保持原始换行和权限，写入通过同目录临时文件替换。

默认文件响应最多 256 KiB，工具输出最多 64 KiB，搜索最多 200 条匹配，均返回截断信息。命令使用 argv、固定 cwd、明确环境变量和 60 秒超时；持续排空输出，只保留有限内容。Linux 子进程单独分组，超时或取消先 TERM，再限时 KILL 和回收。主动脱离进程组的程序不属于支持范围。

第六天接通循环。默认最多 10 次模型调用，按顺序执行工具，保留请求与结果配对。写入、命令、MCP 和插件工具逐次确认；未命中禁止规则的内置只读工具无需确认。参数校验、安全策略和执行前插件检查通过后，才展示待批准的实际操作。拒绝、失败、取消和结果未知分别记录，无法确认停止时不继续本轮操作。

### Session 与项目说明

第七天完成 Session 的新建、列表、切换和保存。一个 Session 一个带版本的 JSON 文件，包含 ID、项目、消息、工具记录及任务状态。默认目录为 `~/.local/state/e-agent/projects/<规范化项目路径哈希>/sessions/`，允许 `--data-dir` 覆盖。

第一阶段采用原子快照写入与项目级进程锁。第二阶段同一项目仍只有一个协调进程持锁，子任务通过协调进程保存独立 Session，子进程不争抢项目锁或直接写共享记录。保存时点包括接受输入、模型回复、工具开始与完成、任务结束；保存失败阻止进一步操作。第八天恢复中断任务：未开始调用补记 not_executed，已开始而无结果则记 outcome_unknown；不自动重放历史工具。损坏记录和未知版本保留原样并拒绝加载。

固定项目约定由根目录 `AGENTS.md` 提供，保留已有能力路径 `project-memory`，其含义收窄为项目说明文件。每次任务开始读取一份快照，标记路径与内容哈希；默认最多 8 KiB。不存在则继续，读取错误或超限则说明并停止本轮。第一版不加载上级和嵌套指令，不自动从对话写回文件。

### 第九天 基础 Skills

启动时扫描项目 `.e-agent/skills/` 及用户配置的 Skills 目录。每个 Skill 以 `SKILL.md` 为入口，安全解析 frontmatter 的 name 和 description，只把目录元信息提供给模型；重复名称全部排除并报错，不靠目录顺序隐式覆盖。

提供 `/skills`、`/skill <name>` 和只读 `load_skill` 工具。正文按需加载，默认最多 32 KiB。只允许读取已发现的 Skill 及其目录内引用文件；不执行附带脚本，不导入 Python。Skill 状态与内容记录保存进 Session；同名同版本去重，重新加载不同版本时显示变化。

模型自行加载时正文通过对应工具结果进入历史；用户命令加载时添加带来源的说明记录。构建请求时只包含一次，不能既写历史又额外全量注入。正文参与上下文预算和后续摘要，恢复时保留历史版本而不静默重读磁盘。需要完整说明时仍可再次调用加载工具获取。

### 第十天 基础 MCP

用户通过显式指定的配置文件启用服务，配置包含服务 ID、可执行文件、argv 和环境变量引用。没有显式配置时不启动服务，不自动信任仓库中附带的服务配置。

使用官方 MCP Python SDK 完成 stdio 子进程连接、初始化、能力协商、分页 tools/list 和 tools/call；具体依赖版本在实现时锁定。进程生命周期归应用所有，连接和调用有期限，退出时关闭连接与回收进程。stdout 留给协议，stderr 作为受限诊断日志，不打印凭据。

服务工具映射到符合模型名称约束的稳定名称，保留原始服务 ID 与工具名；名称采用来源前缀与短哈希，注册时仍检查冲突。文本结果及 structuredContent 转为有界工具结果；isError、协议异常和不支持内容分别标记。第一版不处理图像、音频、resources、prompts、服务端采样和远程授权。

初始化失败只禁用该服务。调用后失联或超时可能已发生副作用，记录 outcome_unknown，关闭受影响连接并停止本轮，不自动重连重发。取消尽力通知服务并清理本程序启动的进程，不承诺撤销已经产生的外部效果。

协议依据：[MCP 工具](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)、[stdio 传输](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)。

### 第十一到十二天 上下文压缩

Session 原始历史与模型输入视图分开。视图由系统指令、当前项目说明、Skill 目录、工具定义、有效摘要及保留的近期消息组成。已加载 Skill 正文属于消息历史，和其他材料一起计入预算。

第十一天实现 `/compact`，仅在空闲且工具结果完整时执行。保留最新用户目标及近期完整对话组，旧 assistant 的工具请求和全部结果不得拆开。摘要包括目标、已改文件、测试结果、失败和待办，并注明它是历史概括，不是新的执行授权。

摘要输入使用上一份有效摘要加上新进入压缩范围的完整历史，记录覆盖到哪个稳定消息 ID。原始记录不删除；摘要及保留边界一次性保存后才切换视图。摘要失败、为空、截断、取消、不缩小或保存失败时沿用旧视图。重启从最后成功状态恢复，不重复注入已覆盖历史。

第十二天在新用户任务以及工具批次完成后的下一次模型调用前检查预算。有可靠计数器时计入工具定义及输出 token 预留；否则采用显式标为估算的 UTF-8 字节预算，默认总上限 128 KiB、回复预留 16 KiB，在可用输入预算的 80% 处尝试压缩。它不能替代提供方限制，实际服务端超限仍需处理。

同一次待发送请求最多自动压缩一次，包括服务端超限后的恢复尝试。摘要调用不进入普通 Agent 循环，不提供工具，不能递归触发压缩。摘要输入自身装不下、没有可压缩旧消息或压缩后仍超限时明确失败，提示减少当前输入、工具数量或新建会话；不在本轮做递归分块摘要。项目说明、Skill 目录和工具定义本身过大时不能靠丢弃工具配对解决。

### 第十三天 本地插件

只加载用户显式配置的本地 Python 模块，入口注册接口包含工具、斜线命令、before_tool 和 after_tool。插件声明 ID 与接口版本；按配置顺序加载，先暂存注册项，全部通过后提交。重名、版本不兼容或加载异常时撤销本次注册，保留原程序能力。

before_tool 只能检查和拒绝，不能改写参数或批准动作；它失败时阻止操作。after_tool 在真实结果持久记录后触发，仅用于观察；失败不能改写结果或重跑工具。插件工具遵循异步执行与协作取消约定，不允许阻塞事件循环。

插件在同进程运行，仅支持可信代码，接口限制不是对恶意插件的安全隔离，也无法保证强制终止任意阻塞原生代码。注册撤销只撤销注册表，不声称回滚 Python 导入时的副作用。提供 `/plugins` 状态列表；修改配置并重启才能禁用或启用，不做热更新。

### 第十四天 CLI 与完整验收

用 Rich 改善 Markdown、代码块和工具结果显示，用 prompt_toolkit 提供多行输入、进程内历史及补全。Enter 换行、Esc 后 Enter 提交，帮助中说明快捷键。状态区展示项目、模型、Session、等待、执行和压缩状态，不把动画冒充模型 token 流。

保留 `--plain` 与非 TTY 自动降级，无交互确认通道则拒绝需要确认的操作。最终验收覆盖一个 Skill、一个真实本地 MCP 测试服务和一个插件工具；在压缩后继续修复练习 bug、运行测试并重启恢复。每日完成各自测试，最后一天只补跨功能验证。

### 第一阶段的统一安全策略

第四天开始增加统一策略入口；第六天接入实际分发。顺序固定为参数校验、规范化目标、安全策略、插件拒绝检查、必要确认、执行前复查、记录开始、执行和记录结果。策略返回 allow、deny 或 ask，记录规则版本、来源、规范化目标及决定理由；插件只能收紧决定。内置普通读取默认 allow，写入、命令和扩展工具默认 ask，规则禁止的操作直接 deny，不允许一次确认覆盖禁止项。

安全配置只从用户显式指定的可信配置加载，在一次任务开始时固定。项目文件、Skill、工具输出、摘要及子任务结果都只能提供内容，不能改变策略、启用服务或生成批准记录。不依赖模型识别恶意文本；固定模型请求受保护操作的测试必须仍被宿主拦截。防提示注入的目标是保持权限边界，不承诺模型永不受误导。

第五天给内置读取、查找和搜索统一增加敏感路径规则，默认拒绝 `.env`、`.env.*`（允许 `.env.example`）、私钥文件及 `.aws/`、`.ssh/` 等凭据目录。例外只能由用户从可信配置显式指定。已知配置凭据在模型输入、工具结果、终端和持久记录的共同出口替换；流式阶段使用跨分片的匹配缓冲，无法确定时暂缓展示。Session 目录和文件分别采用仅当前用户可访问的权限；完整历史指保留完整消息关系，不承诺存储未脱敏原文。未知密钥不能保证识别。

确认展示规范化路径、编辑差异或实际 argv、cwd、环境变量名称及网络边界；不展示凭据值。批准只绑定本次调用、参数、目标版本及策略版本。执行前重新核对文件哈希、目标和父目录链接；不一致返回拒绝并要求重新读取。文件工具使用目录描述符和不跟随链接的操作缩小检查与使用之间的竞态，禁止覆盖新出现的文件；不宣称可以防御同权限恶意进程的所有竞争。

第一阶段命令仍拥有当前用户的系统权限，cwd 和 argv 不是沙箱。命令环境采用允许列表，默认不传模型密钥；MCP 只获得配置指定的凭据。插件和 MCP 服务启动即可能执行代码，逐次工具确认不能限制启动副作用。同进程插件始终只支持可信代码。第十四天必须验证这些限制的说明与实际行为一致。

### 第 15 到 16 单元：事件与流式输出

先从主循环提取应用内部的运行入口，再增加事件订阅，不先发布多个 SDK 包。事件带协议版本、project/session/run 标识、递增序号，工具事件另带调用 ID；定义任务、模型消息、工具、压缩和确认的开始、更新、结束。终结事件只出现一次，发生在清理和最终保存之后。持久化失败时以失败终结并说明未保存，不能发成功终结。显示增量不等于完成记录；恢复只信任最终保存的消息及中断标记，不重放 UI 增量。

第十六单元接入模型流，收集完整文本和工具参数，完成合法结束原因、Schema 及安全检查后才执行工具。断流保留可见的部分回复但标为未完成，不能把半个工具请求加入下一次模型输入。工具进度使用有界事件缓冲和输出上限，慢订阅者允许合并或丢弃进度并标记截断，不丢失终结结果或拖垮工具进程。保留非流式提供方适配。

扩展增加会话、任务、压缩、退出通知和有界命名空间状态保存；观察回调不能改写历史事实或授权。回调失败应可见，退出回调有期限且不阻止清理。不增加任意修改模型输入或审批结果的钩子。CLI 改为事件消费者，`--plain` 同样显示真实增量。

### 第 17 单元：运行中输入

输入编辑与运行并发，提供 steer（调整当前任务）和 follow-up（当前任务完成后启动）的独立队列。提交后立即保存稳定消息 ID 和队列状态；steer 只在完整模型回复与工具批次结束后的下一次请求前消费，follow-up 只在成功终结后消费。每条仅消费一次，队列上限默认 20 条、每条 32 KiB，超限拒绝而不丢弃已有消息。

运行期间只接收追加消息、状态和取消；切换 Session、手动压缩及修改授权配置仍拒绝。取消或失败后，未消费输入保留为待确认，不能自动启动下一任务；重启恢复同样等待用户继续。压缩不吞掉尚未消费的输入。确认交互有独立输入区域，普通追加消息不能被误判为批准。

### 第 18 单元：无界面运行接口

提供应用内 run、cancel、subscribe 及状态查询接口，交互 CLI、单次 CLI 与父任务调度共用此入口。单次模式从参数或 stdin 获取任务，文本模式输出最终结果，JSONL 模式 stdout 只输出版本化事件，诊断走 stderr。退出码约定为 0 正常结束、1 运行失败、2 输入或配置错误、3 因权限无法继续、130 已取消；正常结束不代表模型声称的测试必然通过，仍以工具结果为准。

第一版无界面运行只允许策略已允许的只读操作；遇到 ask 时返回拒绝并将本次运行标记为权限阻塞，不能等 stdin 批准，也不增加跳过确认开关。后续隔离 worker 使用协调进程的审批通道，未连接通道仍默认拒绝。此模式不提供远程 RPC 服务。

### 第 19 单元：只读子 Agent

父任务以 delegate 工具委派任务；首版支持单个、有限并行和结果传递的顺序链，不做任意 agent 间聊天。配置包括角色、模型、工具允许列表、任务和必要上下文；父历史不默认整段复制。初始只允许内置 read/find/search，不开放命令、MCP、插件工具或进一步委派。父进程中的多个运行实例使用独立 Session、上下文和取消令牌，共用事件循环；子结果按结构保存成功、失败、取消或结果未知，部分失败不能变成整体成功。

默认最多 4 个并发、每次委派最多 8 个任务、深度 1；子任务工具权限是父任务权限与角色配置的交集。整个任务树默认最多 30 次模型请求及 15 分钟总时限，每个子任务仍受 10 轮限制；压缩也计入总请求数。并发请求开始前原子预留额度，按输入 token 与各请求最大输出预留 token，实际用量返回后结算。默认累计 token 预算 100000；无可靠计数或价格时展示估算，不能声称精确费用硬上限；准确 token 预算模式下计数不可用则拒绝启动。已知价格时汇总费用，不把未知费用当成零。

父进程统一落盘子记录和任务树索引，子任务记录带 parent_run_id。取消父任务先取消排队子任务，再取消运行子任务并等待清理；无法确认停止则标记未知并阻止继续操作。父失败同样收拢子任务。恢复只展示任务树和已完成结果，任何未完成子任务都不自动重启，允许用户明确重新委派并使用新 ID。

### 第 20 单元：隔离写入与变更合并

在允许多个 worker 写代码前，提供 Linux 本地容器执行适配。预检容器运行时、只读基础文件、非特权用户、能力限制、进程及资源限制、关闭网络和挂载范围；预检失败直接拒绝受限命令，不回退宿主执行。默认只挂载当前工作副本为可写，隐藏宿主凭据、主项目 `.git`、容器管理 socket 和其他副本。资源默认内存 1 GiB、CPU 1 核、进程数 64，超时沿用命令期限。容器镜像由用户明确配置并固定摘要，不自动拉取；容器取消由宿主协调进程停止整个容器。

模型、审批和持久记录保留在可信协调进程，worker 的文件工具限制在自己的副本，命令只在容器内运行。子任务修改和命令仍逐次通过父 CLI 展示 agent 身份及实际操作，串行询问并绑定调用，不能用父任务已批准委派代替具体批准。禁止 worker 使用宿主插件和 MCP；它们不属于这一隔离边界。

工作副本使用独立 Git worktree 和固定基线；创建前要求主工作区干净，非 Git 项目或有用户未提交改动时拒绝并保留现状，不自动 stash/reset。协调进程管理 worktree 元数据，worker 不接触主项目 Git 元数据。子任务完成仅提交变更清单和差异，不直接改主目录；文件读写工具权限不构成整个 worker 的宿主隔离承诺，命令边界由容器承担。

合并由父协调进程串行处理，重新核对基线、主目录状态与改动路径，走普通权限和逐次确认。基线已变化或冲突时停止并保留副本，由用户决定后续处理，不能自动覆盖。完成合并后在受限环境重新验证，失败保留差异和真实结果，不自动撤销用户变化。只有已明确接收或明确丢弃的工作副本才可清理，失败和结果未知副本默认保留。

### 第 21 单元：协作验收与阶段边界

第一阶段完成第 1 到 14 单元及原十份规格和 execution-safety 中第一阶段要求的验收；第二阶段再完成新增四份规格及既有规格中标注第二阶段的要求。第 21 单元串联读取委派、并行 worker、审批、隔离测试、串行合并、失败取消和重启恢复。至少一次真实模型与真实容器验收；没有凭据或容器环境就保留对应任务未完成。

模型切换、多提供方、图片输入、会话树/fork、提示词模板、导出和插件热更新暂不纳入这两阶段。协作所需角色可指定已配置的兼容模型，不等于完整模型管理。会话分支与工作区回滚是不同能力，本轮不提供自动回滚。

## Risks / Trade-offs

- [增加开发量] → 天数只是开发单元，安全任务不挤到最后一天，第二阶段有独立入口验收。
- [同进程扩展拥有宿主权限] → 显式可信加载，不把策略钩子或容器工具包装宣称为插件沙箱。
- [并发预算与取消竞争] → 统一协调者预留额度、记录终态，清理不明确时停止后续动作。
- [工作副本不是安全隔离] → 文件隔离解决改动冲突，容器限制命令权限，两者分别测试。
- [摘要可能遗漏事实] → 保留近期原文和完整消息关系，不把摘要当作执行成功或批准证据。
- [真实模型行为不稳定] → 固定响应验证框架，真实模型、MCP 与容器另外验收，环境不足时保留未完成。

## Migration Plan

当前只有规划，无实施数据。本次保留原有任务编号，向第一阶段加入安全要求，并新增五份能力规格和第 15 到 21 单元；不勾选任何实施任务，不修改教程、源码或参考仓库。

第一阶段 Session 使用版本化快照。第二阶段显式迁移旧快照并保留备份，增加事件版本、输入队列及父子关系；失败或未知版本不覆盖。项目锁继续由唯一协调者持有，不允许多个独立写入者。用户已授权按阶段实现全部单元；开发过程允许子 Agent 分工，产品功能仍遵守阶段边界。
